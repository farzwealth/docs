title: Account lifecycle and plans
description: Current unified API contracts, workflow and activation boundaries.
---

Account status/actions/history support reviewed changes to residence, age band and adulthood, plus reversible deactivation/reactivation. The backend retains financial records, encryption wrappers and consumed trial dates. Deactivation is not deletion; optional consents are withdrawn and current durable work is fenced/canceled. Reactivation does not automatically regrant consent or restart a trial. Sensitive commands use current revisions, explicit confirmation, UUID idempotency and signed recent authentication as specified in the contract.

Paused owners retain limited profile/account, privacy, export and security access. Ordinary finance and new optional grants remain denied. Client-supplied access-purpose or privileged customer flags cannot grant exceptions.

GET `/plan` returns server-evaluated access. GET `/trial` exposes reviewed availability; POST requires the current terms version and explicit acceptance/confirmation. Trial activation is unavailable without approved terms/country policy. The app-managed14-day no-card lifecycle does not charge on expiry and does not grant AI, developer API or MCP access. Billing is unconfigured, and verified provider Paid entitlement remains separate. Farz does not use Clerk Billing.

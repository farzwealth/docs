Budget list/write schemas are endpoint-specific. Posted spending and explicit reversals come from backend finance rules; lending is not budget spending. Do not assume the old generic paginated BudgetItem contract.

Private operations require an authorized Clerk user bearer and workspace membership. Optional/sensitive services retain their policy/entitlement/fresh-authentication gates.

Reviewed repetition has separate preview/commit routes; explicit selected months/revisions and confirmation are required. A repeated budget is a plan, not money spent. `/budgets/page` adds bounded period-filtered discovery.

| Complete route | Authentication | Required operation headers | Declared success |
| --- | --- | --- | --- |
| `GET /api/v1/workspaces/{workspace_id}/budgets/page` | Clerk user bearer | — | 200 application/json RecordPage_BudgetResponse_ |
| `GET /api/v1/workspaces/{workspace_id}/budgets` | Clerk user bearer | — | 200 application/json BudgetResponse[] |
| `POST /api/v1/workspaces/{workspace_id}/budgets` | Clerk user bearer | `Idempotency-Key` | 200 application/json BudgetResponse |
| `POST /api/v1/workspaces/{workspace_id}/budgets/repeat/preview` | Clerk user bearer | — | 200 application/json BudgetRepeatPreview |
| `POST /api/v1/workspaces/{workspace_id}/budgets/repeat` | Clerk user bearer | `Idempotency-Key` | 200 application/json BudgetRepeatReceipt |

---
title: Statement intake and review
description: Current unified API contracts, workflow and activation boundaries.
---

The API exposes raw CSV/XLSX upload, quarantine status, scan/extraction jobs, paginated rows, mapping/review, reconciliation, confirmation, commit and compensation/history. Production capabilities report imports `not_configured`: processing needs an approved isolated scanner/parser executor policy. Declared routes do not prove processing activation or Web integration.

The raw `/imports/uploads` endpoint uses exact MIME, `X-Farz-Filename` and UUID `Idempotency-Key`, not multipart. For account-bound intake, provide all four account/revision/period headers together as declared in OpenAPI. Read `/imports/limits` for current bounded intake policy. Ordinary command bodies remain JSON; never infer that every POST accepts raw bytes.

Follow upload → clean scan → extraction → complete paged rows/review → reconciliation checks → explicit confirmation → commit. Read every page and acknowledge current reconciliation/duplicate/period decisions; a sample cannot authorize the whole file. Atomic ordinary selections cap100rows. Larger batches explicitly acknowledge partial commits and use freshly reviewed/confirmed bounded checkpoints; earlier committed checkpoints are not silently undone after failure.

Matching retries preserve the command key and exact content; changed content conflicts. Retained history and authorized compensation are distinct from deleting financial records. Cancellation does not undo previously committed money.

PDF/image extraction is currently unavailable. Farz will use approved model-native vision, **never OCR**, behind quarantine, isolated bounded preparation, consent, Trial/Paid entitlement, model/privacy/cost and explicit review/confirmation gates. Free users retain deterministic CSV/XLSX and manual entry. Do not activate AI or processing by supplying a client URL, model name, executable or policy ID.

---
title: Recurring plans and rent
description: Current unified API contracts, workflow and activation boundaries.
---

Recurring and rent plans project obligations; they do not charge a bank or prove nonpayment. Overrides, business-day rules, calendar display and reviewed rent proration/amendments preserve original and adjusted dates separately. GET pages provide bounded discovery; legacy arrays remain available.

Confirmed recurring posting previews compare expected and actually paid amounts and bind current source/account/occurrence revisions. Commit records a balanced actual income/expense with the declared UUID key and explicit actual confirmation. Reversal uses the existing append-only correction rules. No automatic payment scheduler is installed.

Rent receipt matching links actual eligible payment sources to plans; unmatching does not fabricate a refund. Use the exact preview, receipt and amendment schemas rather than inferring payments from a forecast.

## Public availability check

No key is required for this request:

```bash
curl --fail-with-body https://api.farz.app/api/v1/capabilities
```

The response includes supported currencies, identity configuration and integration availability. On11 October2026, `personal_api`, `mcp`, `billing`, `email`, `ai` and `imports` are `not_configured`; `lending_available` is true. Availability can change, so inspect the current response.

```bash
curl --fail-with-body https://api.farz.app/api/v1/health/ready
```

Readiness returns `{"status":"ready"}` when the API's schema/runtime-role prerequisites pass. This does not certify every external integration, recovery gate or native client.

## Authenticated first-party requests

Sign in through [the dashboard](https://dash.farz.app) using Clerk and finish account setup. The official client gets a short-lived Clerk user session bearer from the supported SDK and calls `GET /api/v1/me`. Its `workspace_id` is null before onboarding; use the returned workspace ID for private routes afterward.

```http
GET /api/v1/workspaces/{workspace_id}/accounts HTTP/1.1
Host: api.farz.app
Authorization: Bearer <current_clerk_user_session_token>
```

The accounts response is an **array** of `AccountResponse` objects. `balance` is a decimal string and `currency` is a separate field. It is not the previously documented developer `items`/`Money`/`has_more` envelope. See [accounts](/docs/api/accounts).

Unsigned `GET /api/v1/me` returns401. Do not substitute a Clerk secret key, publishable key, another user's token or a developer API key. There is no working Developer API Keys setup flow to follow today.

Use [first-party examples](/docs/developer/examples) within an authorized Clerk integration. The docs origin is not granted production financial CORS access: only `https://dash.farz.app` is approved until further activation.

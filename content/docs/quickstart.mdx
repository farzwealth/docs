## Who can use it

Access needs one of these:

- An active **Paid** plan.
- A **staff-granted beta access grant** for personal API keys. Staff can grant it for up to 90 days.

A Free account and a Trial account do not qualify on their own. Signup is for adults aged 18 and over in AE, SA, BH, KW, QA and OM.

## What you will need

1. A Farz account with one of the access routes above.
2. A personal API key. You create it in the Farz app's personal integration settings. The exact screen name is to be confirmed.
3. A terminal with `curl`, or Python 3 for the [Python example](/docs/developer/examples).

## Check your plan first

The plan data that the Farz apps read includes a `developer_api_available` flag. It is `true` only when your account can use the developer API. Check it before you create a key.

## Create a key

Create the key in the Farz app, with the scopes you need:

| Scope | Lets you read |
| --- | --- |
| `profile:read` | Your locale, base currency and timezone |
| `accounts:read` | Your accounts, as masked summaries |
| `transactions:read` | Your posted transactions in a date range |

Accept the personal-use terms. Choose an expiry between 1 and 90 days. The default is 30 days. Copy the secret when it is shown, because it is shown once.

## Store the key

Keep the key out of your shell history and out of files you share. Export it for one session only:

```sh
export FARZ_API_BASE='https://api.farz.app/api/developer/v1'
read -r -s -p 'Paste your Farz personal API key: ' FARZ_API_KEY
printf '\n'
export FARZ_API_KEY
```

Clear the variables when you finish:

```sh
unset FARZ_API_KEY FARZ_API_BASE
```

## Read your profile

```sh
curl --fail-with-body "$FARZ_API_BASE/profile" \
  -H "Authorization: Bearer $FARZ_API_KEY" \
  -H "Accept: application/json"
```

The response has three fields. Here is an example with made-up values:

```json
{
  "locale": "en",
  "base_currency": "AED",
  "timezone": "Asia/Dubai"
}
```

## List your accounts

```sh
curl --fail-with-body --get "$FARZ_API_BASE/accounts" \
  -H "Authorization: Bearer $FARZ_API_KEY" \
  -H "Accept: application/json" \
  --data-urlencode "limit=20"
```

Example response with made-up values:

```json
{
  "items": [
    {
      "id": "22222222-2222-4222-8222-222222222222",
      "currency": "AED",
      "kind": "bank",
      "masked_reference": "1234",
      "revision": 4,
      "archived": false
    }
  ],
  "next_cursor": null,
  "revision": 17
}
```

Each account has an ID, a currency, a kind, up to four masked digits and a revision. The developer API does not return balances or account names.

## Read transactions

`start` and `end` are required. Both dates are inclusive. The range cannot be longer than 366 days.

```sh
curl --fail-with-body --get "$FARZ_API_BASE/transactions" \
  -H "Authorization: Bearer $FARZ_API_KEY" \
  -H "Accept: application/json" \
  --data-urlencode "start=2026-10-01" \
  --data-urlencode "end=2026-10-10" \
  --data-urlencode "limit=50"
```

Example item with made-up values:

```json
{
  "id": "33333333-3333-4333-8333-333333333333",
  "type": "expense",
  "amount": "25.50",
  "currency": "AED",
  "occurred_on": "2026-10-09",
  "account_id": "22222222-2222-4222-8222-222222222222",
  "to_account_id": null
}
```

The `amount` is a decimal string. Keep it as a string.

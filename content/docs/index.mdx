Verified against the deployed API on **16 October 2026**. The current first-party backend is **https://api.farz.app/api/v1**. Web, Android and the separate Swift iOS client share this versioned backend and Clerk user bearer authentication; native private screens remain gated pending security acceptance.

| Surface | Current status |
| --- | --- |
| Unified `/api/v1` | Live on schema0076;224 paths/264 operations for authenticated workspace finance, onboarding, privacy and notifications |
| Paid developer API keys | Deferred; no published key-issuance flow |
| `/api/developer/v1` | Unavailable; advertised account/transaction routes return404 |
| MCP | Unconfigured; `/mcp` returns404 |
| Third-party OAuth / PKCE | Unavailable; do not use the former discovery/token examples |
| Billing, email, AI and general import integrations | Reported `not_configured` by live capabilities |

The earlier version of this site described a planned developer API as live. Its developer-key setup steps, endpoint shapes, read scopes, OAuth tokens and MCP tool instructions were not a working production contract.

Start with the [safe public quickstart](/docs/quickstart), [authentication](/docs/concepts/authentication), [complete route index](/docs/api/endpoints) and [live OpenAPI JSON](https://api.farz.app/openapi.json). Check `GET /api/v1/capabilities` before assuming an optional integration is enabled. Public schema visibility does not grant financial access.

Personal lending is live: [Reclaim](/docs/api/lending) records money actually received, including partial repayments. It does not initiate a payment or create a reminder.

Future Paid developer keys must be Clerk-issued and authorized by backend-verified payment entitlement. Farz does **not** use Clerk Billing. Key issuance, scopes and delegated access remain separate implementation/activation work, not instructions you can follow today.

## Latest backend additions

The current release includes [private reminders/inbox](/docs/api/notifications),
[20-group owned-record exports](/docs/api/owned-records),
[record browsing and sync](/docs/api/discovery),
[privacy requests and consents](/docs/api/privacy),
[account lifecycle and plan status](/docs/api/account-control),
[session controls](/docs/api/security), expanded actual money/reporting workflows
and [signed provider ingress](/docs/api/webhooks). Their schemas are live; email,
automatic notification transport, full erasure/portability and native security
acceptance are separate gates. [Statement intake/review](/docs/api/imports) routes
exist, but production processing remains unconfigured. PDF/image extraction will
use approved native model vision, never OCR; it is not activated.

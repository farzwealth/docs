---
title: Authentication
description: How the Farz app, the personal developer API and MCP each authenticate, and which credential to use.
---

Farz uses three kinds of credential. Each one works only with its own surface.

| Credential | Used for |
| --- | --- |
| Signed-in user token (Clerk bearer) | Every route under `/api/v1`, used by the Farz apps |
| Personal API key | The personal developer REST API under `/api/developer/v1` |
| OAuth access token from the Farz authorization server | The MCP server at `https://mcp.farz.app/mcp` |

## Signed-in user token

The Farz apps send the signed-in user's token on each request:

```http
Authorization: Bearer <token>
```

This token belongs to the Farz apps. Do not build your own client on it. Use a personal API key, or an approved MCP connector, instead.

## Personal API key

A personal API key lets one private script or backend read your own data through the developer REST API. The key is a Clerk-issued credential. Farz also keeps a grant record for it, and checks that record on each request.

- You create the key in the Farz app's personal integration settings. The exact screen name is to be confirmed.
- You must accept the personal-use terms when you create the key.
- The key expires in 1 to 90 days. The default is 30 days.
- The key secret is shown once, when it is created. Store it in a secret store.
- A key works only while its grant is active, your plan allows it, and its scopes cover the route.
- Revoke a key in the app when you no longer need it. Revocation takes effect on the next request.

Send the key in the same header:

```http
Authorization: Bearer <personal-api-key>
```

Never put a key in a URL, a browser bundle, a shared file, a log or a screenshot.

## OAuth for MCP

The MCP server uses OAuth 2.0 authorization code with PKCE (method `S256`). See [OAuth](/docs/oauth) for the flow.

## Access rules for every credential

- Access is limited to your own personal workspace. A request cannot name another user or workspace to read.
- Each request checks your current plan, your lifecycle state and your scopes. A downgrade, suspension or deletion stops access.
- A missing or invalid credential returns `401`. A valid credential without the needed plan or scope returns `403`.

---
title: Pagination
description: How list routes page through results, for the Farz app API and the personal developer API.
---

Long lists come in pages. Each page returns a cursor when more records exist. Pass that cursor to the next request to get the next page.

## Personal developer API

**Status: Planned.**

| Parameter | Type | Default | Limit |
| --- | --- | --- | --- |
| `limit` | integer | 50 | 1 to 100 |
| `cursor` | string | none | up to 4096 characters |

Each page has `items`, `next_cursor` and `revision`. Keep requesting pages until `next_cursor` is `null`.

- A page can be empty and still have a `next_cursor`. Keep going until the cursor is `null`.
- A cursor expires after 15 minutes.
- A cursor is tied to your query, your credential and your workspace. Keep the same `start`, `end` and other filters for every page. Changing the `limit` is allowed.
- If the cursor expires or your filters change, start again without a cursor.
- Do not decode or change a cursor.

```sh
curl --fail-with-body --get \
  "https://api.farz.app/api/developer/v1/transactions" \
  -H "Authorization: Bearer $FARZ_API_KEY" \
  --data-urlencode "start=2026-10-01" \
  --data-urlencode "end=2026-10-10" \
  --data-urlencode "limit=50" \
  --data-urlencode "cursor=$FARZ_NEXT_CURSOR"
```

## Farz app API

**Status: In testing.** Routes under `/api/v1` use one of three paging styles. The guide for each route shows which one applies in its Query column.

| Style | Parameters | Response |
| --- | --- | --- |
| Limit only | `limit` | An array, or a page with `items` |
| Cursor | `limit`, `cursor` | A page with `items` and `next_cursor` |
| Revision | `limit`, `before_revision` | A page with `items` and `next_before_revision` |

Some record lists have a `/page` route, such as `/accounts/page`, that returns a page. The same resource may also have a plain list route. Check the route in the API reference.

Pass each cursor back exactly as received. A cursor that no longer matches returns an error. Restart from the first page.

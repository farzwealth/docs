title: Conventions
description: Money as decimal strings, dates, IDs, currencies, idempotency and response shapes used across the Farz API.
---

These rules apply across the Farz API. Each guide follows them unless it says otherwise.

## Money

- Every amount is a **decimal string**, such as `"25.50"`. Do not parse it as a binary floating-point number. Use a decimal library for totals.
- An amount always has its currency code next to it. An account keeps its balance in its own currency.
- A negative amount is valid. The record type, such as `expense` or `transfer`, gives the meaning.
- A value that cannot be calculated is `null`. It is not `"0"`. A real zero is `"0"` or an equal decimal.

## Currencies

Native balances are enabled for these currencies: AED, USD, GBP, EUR, SAR, BHD, KWD, QAR, OMR, JOD and TRY. The account currency list in the contract has 164 codes. Use only the enabled list for native balances.

Among the enabled currencies, BHD, JOD, KWD and OMR use three decimal places. The others use two.

## Dates and times

- Dates use `YYYY-MM-DD`. A date range is inclusive at both ends.
- Timestamps use RFC 3339 UTC.
- The reporting timezone is an IANA name, such as `Asia/Dubai`.

## IDs

Resource IDs are UUID strings. Do not assume an order or meaning from an ID.

## Idempotency

Every `POST` that creates a record requires an `Idempotency-Key` header. The value must be a UUID. Use a new UUID for each new request. Reuse a key only when you retry that same request.

## Responses

- A single resource returns one JSON object.
- A list route returns a JSON array, or a page with `items` and a cursor. See [pagination](/docs/concepts/pagination).
- A successful empty list is `[]` or a page with no items. It is not an error.
- A record that you cannot see returns `404`. The API does not confirm that the record exists.

## Languages

Language values are `en`, `ar`, `fr` and `ru`. English is complete. The Arabic, French and Russian text is an AI-reviewed draft until a human reviewer signs it off.

## Sample data

Examples in these docs use made-up values. Use the IDs and amounts from your own responses.

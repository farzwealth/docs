title: Data conventions
description: Exact decimal strings, endpoint-specific shapes and financial write protection.
---

Financial amounts, quantities and rates use decimal strings. Preserve exact values with Python `Decimal` or a decimal library in JavaScript; do not round through binary floating point. Account balances use `balance: "1250.00"` plus `currency: "AED"`, rather than a universal nested `Money` object.

The11 launch currencies are AED, USD, GBP, EUR, SAR, BHD, KWD, QAR, OMR, JOD and TRY. BHD/KWD/OMR/JOD use3 minor digits; the others use2. Check `GET /api/v1/capabilities` for the versioned registry. Missing FX remains missing; never infer zero or1:1, or claim a provider peg without evidence.

Use UUIDs for identifiers and idempotency keys, ISO dates for dated observations and IANA timezones for user calendar boundaries. Request models reject unknown fields where their schema declares `additionalProperties: false`.

## Request/response headers

- Private requests: `Authorization: Bearer` with the current Clerk user token.
- JSON commands: `Content-Type: application/json`; use `Idempotency-Key` where the operation declares it.
- Private responses: `Cache-Control: no-store`, with `X-Request-ID` for correlation.
-429 responses: `Retry-After` indicates the minimum delay.

Response content types vary: private CSV, JSON and HTML reports are supported by their declared routes. Success status is operation-specific; for example account creation returns201. The API is not read-only.

## Financial commands

Read current revisions, bind confirmation to the reviewed values and submit the declared expected revisions. Keep the same command key on an unchanged retry. A409 requires refreshed review, not silent overwriting. Posted money and corrections use append-only balanced history; do not treat deletion or arbitrary direct updates as a supported reversal.

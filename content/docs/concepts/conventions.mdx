The Farz API enforces strict data conventions designed for financial integrity and predictable client consumption.

---

## Standard Headers

Every request and response utilizes the following standard HTTP headers:

| Header | Direction | Description |
| :--- | :--- | :--- |
| `Authorization` | Request | `Bearer <api_key>` or OAuth token. |
| `Accept` | Request | Must be `application/json`. |
| `Content-Type` | Response | Always `application/json`. |
| `Cache-Control` | Response | `no-store` to prevent shared proxies or service workers from caching private financial data. |
| `X-Request-ID` | Response | Unique UUID generated by the gateway for end-to-end tracing and error reporting. |
| `Retry-After` | Response | Seconds to wait before retrying after a `429 Rate Limited` response. |

## Precision Amounts & Decimal Strings

<Callout type="warn" title="Never Use Binary Floating Point">
  All monetary amounts, holding quantities, exchange rates, and percentages are transmitted as **decimal strings** (e.g. `"1250.00"`, `"0.000125"`). Never cast them to standard JavaScript `Number` or IEEE-754 binary floats in your calculations, as rounding errors will corrupt balance reconciliation.
</Callout>

### Recommended Decimal Libraries

- **Python**: Use Python's built-in `decimal.Decimal` module with explicit precision.
- **TypeScript / Node.js**: Use [`decimal.js`](https://github.com/MikeMcl/decimal.js/) or [`bignumber.js`](https://github.com/MikeMcl/bignumber.js/).

| :--- | :--- | :--- |

| **OMR** | 3 | Omani Rial |
| **JOD** | 3 | Jordanian Dinar |
| **TRY** | 2 | Turkish Lira |

### Money Representation

Every monetary quantity is returned within a typed `Money` object:

```json
{
  "amount": "1250.00",
  "currency": "AED"
}
```

### Distinction Between `null` and Zero

- **`"0"` or `"0.00"`**: Represents a real, verified zero balance or transaction amount.
- **`null`**: Indicates that data or a currency conversion rate is **unavailable** or not applicable. An unavailable valuation is never fabricated as `"0"`.

## Identifiers & Dates

- **Resource IDs**: Standard RFC 4122 Version 4 UUID strings (e.g., `22222222-2222-4222-8222-222222222222`).
- **Calendar Dates**: Formatted as `YYYY-MM-DD` (e.g., `2026-10-10`). All date filters are inclusive.
- **Timestamps**: Formatted in RFC 3339 UTC format (e.g., `2026-10-09T15:30:00Z`).
- **Timezones**: Specified as canonical IANA timezone names (e.g., `Asia/Dubai`, `UTC`).
- **Revisions**: An integer incremented each time an entity's state changes on the server.

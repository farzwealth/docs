---
title: Errors
description: The error bodies returned by the Farz app API and the personal developer API, with their codes and what to do.
---

Every error has a stable `code`, a human-readable `message` and a `request_id`. Quote the `request_id` when you report a problem. It does not contain private data.

## Farz app API

```json
{
  "code": "NOT_FOUND",
  "message": "Not found",
  "request_id": "11111111-1111-4111-8111-111111111111",
  "field_errors": [],
  "retry": false
}
```

`field_errors` lists each invalid field as `{"field": "...", "message": "..."}`. `retry` is `true` only for `429` and `503`.

| HTTP | Code | Meaning and next step |
| --- | --- | --- |
| 401 | `UNAUTHENTICATED` | The token is missing or not valid. Sign in again. |
| 403 | `FORBIDDEN` | You are signed in, but the action is not allowed for your account. |
| 404 | `NOT_FOUND` | The record does not exist or you cannot see it. |
| 409 | `CONFLICT` | The record changed, or the request conflicts with the current state. Read it again, then retry. |
| 422 | `INVALID_INPUT` | A field is invalid. Check `field_errors`. |
| 429 | `RATE_LIMITED` | Too many requests. Wait for `Retry-After`. |
| 503 | `UNAVAILABLE` | A service is temporarily unavailable. Retry later with backoff. |
| Other | `REQUEST_FAILED` | The request failed. Quote the `request_id`. |

An unexpected server failure returns `503` with code `UNAVAILABLE`, a generic message, a `request_id` and `"retry": true`. It does not show internal details.

## Personal developer API

```json
{
  "code": "PAID_REQUIRED",
  "message": "A Paid plan or a staff-granted beta access grant is required.",
  "request_id": "11111111-1111-4111-8111-111111111111"
}
```

| HTTP | Code | Meaning and next step |
| --- | --- | --- |
| 401 | `UNAUTHENTICATED` | The key is missing, expired or revoked. The response includes `WWW-Authenticate`. |
| 403 | `PAID_REQUIRED` | Your plan does not include the developer API. A trial does not qualify. |
| 403 | `INSUFFICIENT_SCOPE` | The key lacks the scope this route needs. Create a key with the scope. |
| 422 | `INVALID_REQUEST` or `INVALID_QUERY` | A parameter is missing or invalid. |
| 422 | `INVALID_CURSOR` | The cursor is not valid. Start again without a cursor. |
| 409 | `CURSOR_EXPIRED` | The cursor expired after 15 minutes. Start again without a cursor. |
| 429 | `RATE_LIMITED` | Too many requests. `Retry-After` gives the wait in whole seconds. |
| 503 | `INTEGRATION_UNAVAILABLE` | The developer API is off or paused for your account. Try again later. |

Errors never show another person's records or an upstream provider's response.

## MCP errors

MCP uses the protocol's own error format. A tool that you have not approved returns `CONNECTOR_NOT_APPROVED`, with a link to approve it in the Farz app. The same limit and pause rules apply as for the developer API.

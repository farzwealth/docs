## Personal developer API and MCP

| Limit | Default |
| --- | --- |
| Requests per minute for one person, across all their keys or connectors | 60 |
| Requests per minute for one key or connector | 20 |
| Expensive report reads running at once for one account | 2 |

When a limit is reached, the API returns `429` with a `Retry-After` header in whole seconds.

## Farz app API

The Farz app API returns `429` when a request limit is reached. It sends `Retry-After` with the wait time. Limits differ by route. They are not published per route in this reference.

## How to respond to a 429

1. Read `Retry-After` and wait at least that many seconds.
2. Retry the same request with a bounded backoff and random jitter.
3. Stop after a few attempts and report the error with its `request_id`.

Do not run more requests in parallel to get around a limit. Lower your polling frequency, or narrow your date range.

---
title: First-party request examples
description: Use current Clerk user tokens and the actual accounts response shape.
---

These examples belong inside an authorized first-party Clerk integration. They do not establish an external developer API or enable native private screens.

```typescript
// getToken is supplied by the supported Clerk SDK in the official integration.
async function readAccounts(getToken: () => Promise<string | null>) {
  const token = await getToken();
  if (!token) throw new Error('Sign in first');
  const headers = { Authorization: `Bearer ${token}` };
  const meResponse = await fetch('https://api.farz.app/api/v1/me', {
    headers, cache: 'no-store', credentials: 'omit',
  });
  if (!meResponse.ok) throw new Error(`Profile status ${meResponse.status}`);
  const me = await meResponse.json();
  if (!me.workspace_id) throw new Error('Complete onboarding in Farz');
  const response = await fetch(
    `https://api.farz.app/api/v1/workspaces/${me.workspace_id}/accounts`,
    { headers, cache: 'no-store', credentials: 'omit' },
  );
  if (!response.ok) throw new Error(`Accounts status ${response.status}`);
  return response.json(); // AccountResponse[], with balance as a decimal string
}
```

Browser financial CORS currently permits only `https://dash.farz.app`; this code is not a drop-in script for the docs origin or an arbitrary third-party website. Tokens are short-lived and must not be persisted in localStorage or logged. For generated types and financial methods use the current backend contract, not the former developer `Money`/`Page` examples.

For public CLI checks, no secret is needed:

```bash
curl --fail-with-body https://api.farz.app/api/v1/capabilities
```
